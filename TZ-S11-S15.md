## Фаза 1 (S11) — Мастер создания поездки + ресайз панели

### Мастер создания (одна модалка в `Discover`, один сабмит `POST /trips/`)

| Поле | Правила |
|------|---------|
| **Город** | Автокомплит по геокодеру (Nominatim), ограниченный **bbox Калининградской области** (хардкодим один раз). Выбор даёт `{city, lat, lon}`; координаты → центр карты поездки. Вне bbox ничего не находится — честная граница покрытия. |
| **Страна/регион** | Статичная подпись «Калининградская область» как задел на будущее, **без выбора**. |
| **Название** | Текст, **обязательно**. |
| **Взрослые** | Число, **min 1**, дефолт 1. |
| **Дети** | Дефолт 0; при `≥ 1` показываем **N обязательных** полей возраста (0–17) → `children_ages`. |
| **Даты** | Два `<input type="date">`, **обязательны**; `start ≥ сегодня`, `end ≥ start`, кап длины **60 дней**. |
| **Валюта** | Дропдаун ₽ RUB / $ USD / € EUR / ¥ CNY. Дефолт по языку i18n: ru→RUB, en→USD, de/fr/es→EUR, fallback EUR. ¥ CNY — только ручным выбором. |
| **Бюджет** | **Опционально**, в выбранной валюте. |

- Возраст — не декоративное поле: идёт в `ticket_child` (авто-оценка ТЗ-E) и в `min_age`/`suitable_for_children`. Пустой возраст даёт кривую оценку → требуем.
- Даты заданы → `sync_trip_days` нарезает `trip_days` (как сейчас).
- Серверный дефолт `Trip.currency='EUR'` не трогаем (обратная совместимость); дефолт задаёт модалка.

### Палитра дней

- `DAY_HEX` расширяем с 6 до **12** различимых тонов, дальше **цикл** (день 13 = цвет дня 1).
- Оговорка: на 60-дневных поездках оверлей «все дни» всё равно нечитаем — длинные поездки планируются по-дневно (аккордеон/пилюля), не по оверлею.

### Ресайз панели

- Дефолт ширины **320 → 400**.
- Тянем за правую границу: хэндл `col-resize` с «мёртвой зоной», чтобы кнопки под него не залезали.
- Мин **320** / макс **`min(640, 50vw)`**.
- Ширина в `localStorage` (одна на все поездки).
- На `<768px` (панель во всю ширину снизу) ресайз **выключен**.
- Та же панель в режиме превью — ресайз работает и там.

### Шапка панели — «спрессовывание» (A + C)

- **flex-wrap:** при нехватке ширины кластеры (лого/шестерёнка · вкладки · экспорт) переносятся на вторую строку, `gap`/паддинги ужимаются. Ничего не обрезается.
- **лёгкий C:** при совсем узкой ширине (близко к 320) текстовые вкладки Маршрут/Бюджет/Meili схлопываются в иконки/короткие подписи.
- Overflow-меню «…» — **не делаем**.

## Фаза 2 (S12) — DnD + транспорт в дне + часы/минуты в оптимизации

### 2.1 DnD внутри дня (возврат «пропавшей» фичи)

- Перетаскивание стопов вернуть **в `DayCard`** (сейчас DnD живёт только в легаси-ветке «без дней»). A B C → C A B.
- Порядок уходит в существующий `POST /trips/{id}/stops/reorder` с id стопов **этого дня** (позиции по-дневные, 0..n; другие дни не трогаются).

### 2.2 DnD целого дня (новый механизм)

**Система отсчёта (зафиксирована на примере):** календарь — фиксированная рамка по возрастанию;
перетаскивание прокручивает **содержимое** дней по датам; бандл наследует дату нового слота.

```
День 1 · Jul 1 — [A, B, C]         Тащим «День 3» наверх:
День 2 · Jul 2 — [D, E]        →   День 1 · Jul 1 — [F, G]
День 3 · Jul 3 — [F, G]            День 2 · Jul 2 — [A, B, C]
                                   День 3 · Jul 3 — [D, E]
```

- Едет **весь бандл дня, кроме даты**: стопы (`day_id`/`visit_date`) + старт/финиш дня + временные рамки (`start_time`/`end_time`). Меняется только то, на какую дату встаёт бандл.
- Календарь строго по возрастанию — Jul 3 никогда не встанет выше Jul 1 (иначе поедет `date`/`day_index` unique-constraint).
- **Новый эндпоинт** `POST /trips/{id}/days/reorder` — принимает новый порядок `day_id`, сервер прокручивает содержимое по фиксированным датам-строкам.

### 2.3 Выпадашка «назначить день» — **остаётся как есть**

- Перенос одиночного стопа между днями — через существующий `<select>` в `DayCard`.
- **Cross-day drag одиночного стопа — не делаем.**

### 2.4 Транспорт между точками в дневном виде (новая правка)

- Тумблер 🚶 🚲 🚗 (`transport_to_next` + `updateStopTransport`) сейчас есть только в легаси-списке. Добавить рендер **под каждым стопом в `DayCard`** (режим редактирования; в превью скрыт). Бэкенд готов — нужен рендер + пересчёт маршрута по плечу.

### 2.5 Бюджет времени оптимизации — часы + минуты

- В селективном режиме `DayCard` вместо одного поля «720 мин» — **две ячейки `N ч` + `M мин`**; внутри сводим в минуты для API.

## Фаза 3 (S13) — Превью чужой поездки + лайк/копирование

### Механика

- **Переиспользуем `TripPlanner` с флагом `readOnly`** (не отдельная страница). Вход: клик по карточке чужой поездки (`RecommendedTrips`, позже — общий список публичных) → `/trips/{id}/preview`.
- Кнопку «Клонировать» с карточки **убираем** — копирование теперь внутри превью.

### Доступ к данным (вариант A — ослабить чтение)

- 4 GET-ручки (`getTrip`, `getDays`, `getLocations`, `getStops`) разрешают чтение, если **owner ИЛИ `is_public`**; мутации остаются owner-only (как сейчас). `readOnly`-планировщик грузится теми же вызовами без расхождения с обычным режимом.
- Приватные поездки по-прежнему 404.
- В ответ `GET /trips/{id}` добавить **`liked_by_me: bool`** (для состояния ❤).

### Что видно в превью

- **Гасим все мутации:** поиск мест, `StartPoint`, крестики удаления, ручки DnD, приоритеты, `<select>` переноса, оптимизацию, тумблеры транспорта, действия карточки точки на карте.
- **Вкладки:** «Маршрут» (read-only список) + «Бюджет» (read-only). Вкладку **«Meili» скрыть** (ассистент пишет в поездку — для чужого ридонли бессмыслен).
- **Карта:** рисуем **маршрут между стопами**, но **без старта/финиша владельца** — никаких 🏁-депо и 🏠-дома; линия соединяет только сами места.
- **Бюджет в превью:** только активности из стопов (**рестораны + достопримечательности**), **без** статей `TripExpense` (жильё/транспорт/еда/прочее), без старта-«дома», без кнопок добавления трат.
- **Шапка превью:** ← назад · название поездки · **❤ лайк** · **⧉ копировать**.

### Действия шапки

- **❤ Лайк** — тоггл, `POST/DELETE /trips/{id}/like` (бэкенд готов), иконка отражает `liked_by_me`.
- **⧉ Копировать** — существующий `POST /trips/{id}/clone` (уже проверяет `is_public`), после успеха → переход в **свою** новую поездку в редактируемый планировщик.

## Фаза 4 (S14) — Регистрация по коду на почту

**Жёсткий гейт (вариант A):** без подтверждённого кода в приложение не попасть.
**До подтверждения `User` в БД не создаём** — pending живёт в Redis.

### Поток

1. `POST /auth/register` → валидация → проверяем, что подтверждённого `User` с таким email ещё нет → кладём pending в Redis, шлём 6-значный код. **Токенов нет.**
2. Экран ввода кода → `POST /auth/verify` (email + code) → сверяем с Redis → создаём **настоящую строку `User`** → выдаём токены (access + refresh-cookie), pending-ключ удаляем.
3. **Resend** — регенерирует код, сбрасывает счётчик попыток; кулдаун **60 сек**.

### Хранение и параметры

- **Pending в Redis:** ключ по email → `{password_hash, name, code, attempts}`, TTL **1 час** (сама протухнет, фоновой чистки нет). Пароль — **хэшем**, не плейнтекстом.
- **Код:** 6 цифр, валидность **10 мин**, до **5** попыток ввода, потом код сгорает.
- **Сквоттинг:** `register` на email с **неподтверждённым pending** (нет строки `User`) → просто новый код + перезапись pending. На **существующего подтверждённого** `User` → ошибка «email занят». Реальный владелец всегда «перехватывает», введя код из своей почты.
- **Колонка `is_verified` не нужна** — все `User` в БД подтверждены по построению. Google-юзеры создаются сразу настоящими; старых мигрировать не надо (миграции нет).
- В dev `email.py` без SMTP пишет код в лог (`docker logs`).

## Фаза 5 (S15) — Оценки мест + вечерний опрос «как вам день»

**Связь `UserVisitedPlace` — юзер↔место, глобальная** (не привязана к поездке): пометив место,
оно «посещено» везде и в рекомендациях (`recommendations.py` уже использует `UserVisitedPlace`).

### Модель данных

- В `UserVisitedPlace` добавить **`comment TEXT NULL`** (миграция, читаемая руками). `rating int NULL` уже есть.
- **Шкала оценки — 1–5 звёзд**, комментарий опционален.
- «Посещено» = наличие строки `UserVisitedPlace`. Ставится **только явным действием** (оценка или тоггл в панели) — не презюмируем.

### Блок в `StopDetailPanel` (десктоп)

- Под блоком «Забронировать через» — блок **Оценка (1–5) + опциональный комментарий**.
- Бэкенд: `POST /places/{id}/visited` (+ `DELETE`), rating/comment опциональны.
- Бейдж **✓** в строке стопа в `DayCard`, если место посещено.
- В **превью** чужой поездки тоггл/оценку **не показываем**.

### Вечерний опрос «как вам день» — **in-app сейчас (вариант C)**

- Настоящий Web Push — **отдельная поздняя фаза** (нужен деплой/HTTPS, которых нет). Модель и UI проектируем так, чтобы пуш лёг сверху без переделок.
- **Триггер:** при загрузке/возврате фокуса в приложение (любая авторизованная страница), если одновременно: локальное время юзера **≥ 20:00**; есть поездка с `TripDay.date` = сегодня; в дне остались стопы, ещё не оценённые и не пропущенные сегодня.
- **UI:** оверлей со **стопкой карточек** по стопам сегодняшнего дня.
  - Оценка (+ опц. коммент) → создаём строку `UserVisitedPlace`.
  - **Свайп влево** = пропустить на сегодня, **строку НЕ создаём**.
- **Несколько активных поездок** (у обеих день = сегодня, редкость): берём последнюю открытую (`lastOpenedTripId` в `localStorage`), чтобы не мешать стопы.
- **Дедуп:** оценённые — серверная правда (строка есть); пропущенные сегодня — ключ в `localStorage` по дате. Когда все стопы дня оценены/пропущены — промпт в этот день больше не всплывает.
- Порог **20:00** — хардкод, не в настройках.

## Сводка новых/изменённых поверхностей

**Бэкенд:**
- `POST /trips/{id}/days/reorder` (реордер дней — прокрутка бандлов по датам).
- 4 GET-ручки трипа: чтение при `owner ИЛИ is_public`; `liked_by_me` в ответе трипа.
- `POST /auth/verify`, доработка `POST /auth/register` (pending в Redis), resend-эндпоинт.
- `POST /places/{id}/visited` + `DELETE`; колонка `comment` в `user_visited_places` (миграция).
- (Готово, не трогаем: `like`/`unlike`, `clone`, `stops/reorder`, `updateStopTransport`.)

**Фронтенд:**
- Модалка мастера создания (город-автокомплит + все поля).
- Ресайз панели + flex-wrap/C-схлопывание шапки; `DAY_HEX` → 12.
- DnD в `DayCard` (стопы) + DnD дней; транспорт-тумблер в `DayCard`; ч/мин в оптимизации.
- `readOnly` через `TripPlanner`/`DayCard`/`StopDetailPanel`/`PlaceSearch`; превью-шапка ❤/⧉; клик по карточке → превью.
- Экран ввода кода в `Auth`.
- Блок оценки+коммента в `StopDetailPanel`; оверлей вечернего опроса; бейдж ✓ в `DayCard`.

**Тесты:** бэкенд — `pytest` (юнит + интеграционные); фронт — `vitest` + при необходимости Playwright (спеки по русским строкам UI).
